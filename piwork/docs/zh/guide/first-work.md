# 第一个 Work

学习如何创建和使用您的第一个 Piwork 工作空间。

## 前置条件

创建第一个 Work 之前，请确保您已：

- ✅ Piwork Core 正在运行（[快速开始](/zh/guide/quick-start.html)）
- ✅ 已创建管理员账户
- ✅ 在 **Admin → Quick setup** 中配置了 AI 模型
- ✅ 运行时准备已完成（所有组件显示 **Ready** 状态）

## 您将学到

- 创建 Work
- 使用 Chat 与 AI 交互
- 管理工作空间文件
- 运行 Service（应用程序）
- 停止和重启 Work
- 导出和导入工作空间

## 步骤 1：打开工作台

完成设置后，工作台会自动打开。您也可以：

1. 从准备屏幕点击 **Open workbench**
2. 或从 Admin 导航栏直接访问

## 步骤 2：创建 Work

1. 在工作台中点击 **New Work**
2. 输入工作空间的描述性名称（例如"我的第一个项目"）
3. 点击 **Create**
4. 等待 Work 达到 **Ready** 状态

### 正在发生什么？

Piwork 正在：
- 创建隔离的工作空间容器
- 设置默认环境
- 加载 Harness 配置
- 准备工作空间目录

## 步骤 3：开始聊天

Work 就绪后：

1. 点击 **Open** 打开 Work
2. 导航到 **Chat** 选项卡
3. 输入消息并按 **Send**

### 试试这些示例

**简单问题：**
```
你能在这个工作空间中帮我做什么？
```

**创建文件：**
```
创建一个 hello.txt 文件，包含欢迎消息
```

**构建应用：**
```
用 NiceGUI 创建一个简单的待办事项应用
```

AI 可以：
- 回答关于工作空间的问题
- 创建和修改文件
- 编写代码和应用
- 运行命令
- 使用工作空间特定的工具

## 步骤 4：浏览文件

**Files** 选项卡显示您的工作空间目录：

- **浏览**文件和文件夹
- **上传**计算机上的文件
- **下载**文件到计算机
- **查看**文件内容

所有文件都在工作空间中持久化 - 它们不是临时的。

## 步骤 5：使用 Service

当 AI 创建带有 Web 界面的应用时：

1. 自动出现新的 **Service** 条目
2. 点击 **Preview** 在嵌入框架中查看
3. 或点击 **Open** 在完整应用选项卡中使用

### Service 示例

- 待办事项列表和看板
- 数据仪表板
- 内容管理系统
- 内部工具
- 带 Web UI 的 API 后端

## 管理您的 Work

### Settings 选项卡

使用 **Settings** 可以：
- 更改 AI 模型
- 调整工作空间配置
- 查看 Work 元数据

**重要：** 点击 **Apply** 激活更改。保存不会自动应用它们。

### 停止 Work

关闭浏览器**不会停止** Work。它继续在服务器上运行。

要停止 Work：
1. 返回工作台列表
2. 打开 Work 的菜单（⋮）
3. 选择 **Stop**

### 重启 Work

停止的 Work 出现在工作台列表中：
1. 找到停止的 Work
2. 点击 **Start**
3. 等待 **Ready** 状态
4. 打开 Work

所有文件、历史和 Service 都被保留。

## 分享您的 Work

### 导出

要与他人分享 Work 或将其移动到另一个 Piwork 安装：

1. **停止 Work**（导出前必需）
2. 打开 Work 的菜单（⋮）
3. 选择 **Export**
4. 下载 `.work` 文件

导出包括：
- 工作空间文件
- 应用代码
- Service 配置
- Harness 状态
- （对话历史是独立的）

### 导入

在另一个 Piwork 安装上导入 Work：

1. 进入工作台
2. 点击 **Import Work**
3. 上传 `.work` 文件
4. Work 以 **Stopped** 状态创建
5. 检查模型和环境兼容性
6. 点击 **Start** 运行

**注意：** 导入不会重放对话历史。目标安装必须具有：
- 兼容的运行时镜像
- 配置的模型凭证
- 足够的资源

## 提示和最佳实践

### 命名 Work

使用标识项目的描述性名称：
- ✅ "客户仪表板"
- ✅ "Q4 报告生成器"
- ❌ "Test123"
- ❌ "我的工作"

### 何时创建新 Work

为以下情况创建单独的 Work：
- 不同的项目或客户
- 实验 vs. 生产
- 不同的技术栈
- 隔离的环境

### 性能

- 停止未活跃使用的 Work
- 导出已完成的项目进行归档
- 监控工作空间磁盘使用情况

### 故障排除

**Work 无法启动：**
- 检查 Core 日志中的错误
- 验证模型凭证有效
- 确保 Docker 有足够的资源

**Service 无法加载：**
- 检查应用是否成功启动
- 查看 Chat 历史中的错误消息
- 验证服务端口正确

**文件丢失：**
- 文件仅在保存到工作空间目录时持久化
- 临时文件（`/tmp`）不会保留
- 检查 Files 选项卡，而非系统临时文件夹
